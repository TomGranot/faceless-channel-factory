# Channel ideas

Good source-led channels have structured discovery, stable item IDs, clear attribution, mobile-readable pages, and enough useful material for a slow scroll.

The strongest researched pilots are Wikimedia Commons Picture of the Day, The Met Open Access collection, Smithsonian Open Access, Library of Congress Free to Use and Reuse, USGS earthquake events, and SEC filings. See the [source feasibility review](research/channel-source-feasibility.md) for API, identifier, rights, and attribution details.

| Channel | Source | Video promise |
| --- | --- | --- |
| Open Source Radar | GitHub search and releases | One new tool worth understanding |
| Demo Paper Daily | arXiv and Papers with Code | A research result you can see working |
| Indie Launch Radar | Launch feeds and maker sites | One small product with a sharp wedge |
| API of the Day | Public API directories and docs | One endpoint and a useful result |
| Dataset Find | Dataset cards and samples | What the dataset lets you investigate |
| Changelog Radar | Product release feeds | The update that changes daily work |
| Automation Recipe | Workflow galleries | Trigger, transformation, result |
| Useful Public Service | Government directories | A service people overlook |
| Design Decision Daily | Curated public interfaces | One UI decision and its consequence |
| Map Story | Open GIS and data journalism | One pattern that geography makes visible |
| Collection Reveal | The Met and Smithsonian Open Access | Guess the object from one strange detail, then learn what it did |
| Package Signal | npm registry and downloads APIs | One package signal, its eight-week trace, and one concrete use |

Start with the source, not the channel name. Test whether ten recent items can pass discovery, rights, capture, and visual-suitability gates before creating accounts.
